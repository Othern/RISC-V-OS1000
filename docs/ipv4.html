IPv4 協議實作

本頁對應目前程式碼中的 kernel/ipv4.c 與 include/ipv4.h。 IPv4 已接在 Ethernet EtherType 0x0800 後方，提供 header 驗證、checksum、 本機位址判斷、收發 helper 與統計輸出。ICMP、UDP、TCP 仍是下一層工作。

目前完成範圍

已完成 Ethernet 收到 0x0800 時呼叫 ipv4_receive()。
已完成 驗證 version、IHL、total length、header checksum、fragment 欄位與目的 IP。
已完成 ipv4_send() 可組 IPv4 header，透過 ARP cache 找 MAC 後送出。
尚未完成 IP fragmentation / reassembly。第一版會丟棄 fragmented packet。
尚未完成 ICMP Echo、UDP socket、TCP state machine。
尚未完成 Route table、default gateway、DHCP、DNS。

資料路徑

1 VirtIO RX
device 完成 RX descriptor，virtio_net_drain_rx() 取得 Ethernet frame。
2 EtherType
若 Ethernet type 是 0x0806 交給 ARP；若是 0x0800 交給 IPv4。
3 IPv4 RX
ipv4_receive() 驗證 IPv4 header，丟棄格式錯誤、checksum 錯誤、fragmented 或不是送給本機的 packet。
4 Protocol
目前只統計 ICMP=1、TCP=6、UDP=17，尚未交給上層 handler。

IPv4 Header

欄位 目前行為
version / IHL 只接受 IPv4，IHL 至少 5。支援 header options 的長度檢查，但不解析 options。
total_length 必須大於等於 header 長度，且不能超過實際收到的 Ethernet payload 長度。
flags_fragment_offset 若 MF bit 或 fragment offset 不為 0，直接丟棄。
ttl 發包預設 64；收包目前不轉送，因此沒有遞減 TTL。
protocol 統計 ICMP、UDP、TCP 與 other。下一步可在這裡接 handler。
header_checksum 收包驗證 one's complement checksum；發包時計算 20-byte header checksum。
src_ip / dst_ip 本機固定為 10.0.2.15。只接受目的位址為本機或 broadcast 的 packet。

發包流程

ipv4_send(dst_ip, protocol, payload, payload_len)
  -> 檢查 payload 長度
  -> dst_ip == 255.255.255.255 ? 使用 broadcast MAC
  -> 否則查 arp_lookup(dst_ip)
  -> cache miss 時送 arp_request(dst_ip)，本次回傳 -2
  -> 建立 20-byte IPv4 header
  -> 計算 header checksum
  -> virtio_net_send_ethernet(dst_mac, 0x0800, packet, total_length)

這個設計讓 ARP resolution 與 IPv4 header 建立分開。之後 UDP/TCP 發包可以共用 ipv4_send()，但要自行處理 UDP/TCP checksum 與重試策略。

QEMU 中的觀察方式

shell 新增 ip 指令，會印出本機 IPv4 與收發統計：

> ip
IPv4 local=10.0.2.15
  rx=0 drop=0 icmp=0 udp=0 tcp=0 other=0
  tx=0 drop=0

TAP 模式下可以用 host 工具送 IPv4 frame，再用 ip 觀察統計變化。 目前尚未實作 ICMP reply，所以 ping 不會收到回應，但 ICMP RX counter 應可增加。
